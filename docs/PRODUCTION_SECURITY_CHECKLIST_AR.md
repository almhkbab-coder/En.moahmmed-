# قائمة التحقق الأمني الشامل لبيئة الإنتاج (Production Security Checklist)
## عيادة الدكتور محمد أحمد الصياد - جراحة العظام والمفاصل الصناعية

---

## 1. أمن وتشفير بيانات المرضى (Patient Data Protection & Cryptography)

- [x] **تشفير البيانات الحساسة أثناء التخزين (Data-at-Rest Encryption):**
  - تم تطبيق خوارزمية **Fernet Specification** (تعتمد تشفير **AES-128 في نمط CBC مع حشوة PKCS7** مصحوبة بمصادقة وسلامة البيانات عبر **HMAC-SHA256** بمفتاح بطول 256 بت / 32 بايت).
  - حقول `full_name` و `notes` في جدول `appointments_patient` تظهر في التخزين المكتوب (PostgreSQL وعلى القرص وفي ملفات `pg_dump`) كنصوص مشفرة غير قابلة للقراءة تبدأ بـ `gAAAAA...`.
- [x] **حماية وعزل مفاتيح التشفير (Key Isolation):**
  - مفتاح التشفير `PATIENT_DATA_ENCRYPTION_KEY` غير مخزن في قاعدة البيانات ولا في مستودع Git.
  - يتم تمرير المفتاح سحابياً عبر متغيرات البيئة المشفرة بالخادم فقط.
- [x] **فهرس البحث الأمني المعمّى (Blind Index):**
  - تم تطبيق خوارزمية `compute_search_token` باستخدام HMAC-SHA256 لتوليد رمز بحث مشفر `name_search_token` يسمح بالبحث والتصفية الدقيقة دون الحاجة لفك تشفير كافة السجلات في الذاكرة.
- [x] **حماية الخصوصية في السجلات الرقابية (Log Privacy):**
  - تم فحص وتعديل كافة استدعاءات `ActivityLog` لضمان عدم تسريب أسماء المرضى أو الشكاوى السريرية إلى سجلات النشاط أو ملفات السيرفر، واستبدالها بالرموز المرجعية العامة `APT-XXXXXXXX`.
- [x] **حماية خصوصية واجهة الاستعلام العامة:**
  - واجهة `/booking/status/` تفرض إدخال الرمز المرجعي مع رقم الهاتف المسجل معاً، مع حجب الاسم الكامل وتشفيره جزئياً (Masked Name)، وحجب ملاحظات الطاقم الداخلي (`staff_notes`) نهائياً.

## 2. نزاهة محرك المواعيد والتزامن (Appointment Concurrency & Integrity)

- [x] **منع التضارب الزمني التام (Interval Overlap Engine):**
  - تم تحصين النظام برمجياً لمنع تداخل الفترات الزمنية ($S_1 < E_2 \land S_2 < E_1$) حتى في حال اختلاف أوقات البدء للأوقات ذات المدد المختلفة.
- [x] **الحماية الجدارية على مستوى PostgreSQL:**
  - قيد فريد شرطي `unique_confirmed_appointment_per_branch_slot` يمنع حفظ أو كتابة موعدين مؤكدين بنفس وقت البدء في نفس الفرع.
- [x] **قفل الصفوف الذري (Row-Level Locking):**
  - استخدام `select_for_update()` داخل معاملات `transaction.atomic()` عند تغيير حالة الموعد، والتعامل الآمن مع اعتراضات التزامن `IntegrityError` وتحويلها لرسالة تنبيهية بالواجهة.
- [x] **عزل الفروع الجغرافية المستقلة:**
  - تعمل الفروع المتعددة باستقلالية كاملة دون أي تأثير لحجوزات فرع على فترات الفرع الآخر.
- [x] **تفريغ الفترات الملغاة والمرفوضة:**
  - يتم الإفراج الفوري عن الفترة الزمنية في الموقع العام لتصبح متاحة للحجز بمجرد إلغاء أو رفض الموعد.
- [x] **حماية سجلات المرضى من الحذف العرضي:**
  - ربط سجل المريض بالمواعيد بقيد `on_delete=models.PROTECT` لمنع الحذف العرضي لبيانات المرضى المرتبطين بمواعيد سابقة.

## 3. المصادقة والصلاحيات والتحكم في الوصول (RBAC & Authentication)

- [x] **تطبيق مبدأ الامتيازات الأقل على مستوى الخادم (Server-Side Least Privilege):**
  - حصر إعدادات النظام وسجلات الرقابة بالمشرف العام عبر `@super_admin_only`.
  - حصر الملف المهني والسيرة الذاتية بالطبيب والمشرف عبر `@doctor_or_admin_required`.
  - حصر إدارة المواعيد بالاستقبال والطبيب وحجب محرري المحتوى عبر `@appointment_staff_required`.
  - حصر إدارة المقالات والفيديوهات بمحرري المحتوى عبر `@content_staff_required`.
- [x] **اختبار الوصول المباشر عبر الروابط (Direct URL Tampering):**
  - اعتراض أي محاولة وصول غير مصرح بها من قبل دور غير مخول وإرجاع كود **HTTP 403 Forbidden** فورياً.
- [x] **الحماية من هجمات القوة الغاشمة (Brute-Force Lockout):**
  - تجميد تلقائي لمحاولات تسجيل الدخول لمدة 15 دقيقة (HTTP 429) عند تسجيل 5 محاولات فاشلة متتالية للمستخدم وعنوان الـ IP.
- [x] **تطهير كلمات المرور والبيانات الافتراضية:**
  - تم إزالة أي بيانات اعتماد ثابتة (`admin/admin` و `reception/admin`) من أكواد النظام واستبدالها بمتغيرات بيئة مشفرة ومولدات عشوائية آمنة.
- [x] **تأمين الجلسات (Session Security):**
  - `SESSION_COOKIE_HTTPONLY = True` لمنع وصول سكربتات XSS لجلسة المستخدم.
  - `SESSION_COOKIE_SECURE = True` في بيئة الإنتاج لضمان مرور الجلسات عبر HTTPS فقط.

## 4. أمان الملفات والوسائط المرفوعة (File Upload Security)

- [x] **استبعاد ملفات SVG نهائياً:**
  - تم حظر وإلغاء دعم امتدادات `.svg` بالكامل في كافة حقول النماذج لمنع ثغرات Stored XSS و XML Entity Injection.
- [x] **التحقق من المحتوى الحقيقي والبايتات السحرية (Pillow Verification):**
  - فحص العينة البايتية للملفات المرفوعة لكشف وحظر أي وسوم مشبوهة (`<script`, `<?php`, `<html`, `onload=`, إلخ).
  - فحص الصور النقطية عبر `Image.open().verify()` للتحقق من سلامة البنية النقطية ومطابقتها لـ `['JPEG', 'PNG', 'WEBP']`.
- [x] **تحديد الحد الأقصى لحجم الملفات:**
  - ضبط سقف الملفات المرفوعة بـ **5 ميجابايت (5MB)** كحد أقصى لمنع استنزاف مساحة الخادم.

---

## 5. أمان الويب وترويسات الحماية (Web Security & HTTP Headers)

- [x] **حماية ضد تزوير الطلبات (CSRF Protection):** مفعلة إجبارياً على كافة النماذج مع تعيين `CSRF_COOKIE_SECURE = True` و `CSRF_COOKIE_HTTPONLY = True`.
- [x] **حماية ضد هجمات Clickjacking:** ضبط `X_FRAME_OPTIONS = 'DENY'`.
- [x] **حماية ضد التخمين بنوع المحتوى:** ضبط `SECURE_CONTENT_TYPE_NOSNIFF = True`.
- [x] **حماية ضد هجمات تصفح الـ XSS:** ضبط `SECURE_BROWSER_XSS_FILTER = True`.
- [x] **تفعيل أمان النقل الصارم (HSTS):** ضبط `SECURE_HSTS_SECONDS = 31536000` (لمدة عام كامل) مع `INCLUDE_SUBDOMAINS` و `PRELOAD`.
- [x] **التحويل الإجباري إلى الاتصال المشفر (SSL Redirect):** ضبط `SECURE_SSL_REDIRECT = True` في الإنتاج.
- [x] **التعامل مع الوكيل العكسي Nginx:** ضبط `SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')`.

---

## 6. التخزين المؤقت المشترك ومكافحة السبام (Cache & Rate Limiting)

- [x] **التخزين المؤقت المشترك (Multi-Worker Shared Cache):**
  - اعتماد جدول كاش مركزي `clinic_system_cache` في PostgreSQL (أو Redis عبر `REDIS_URL`) لضمان مشاركة محددات المعدل وحظر تسجيل الدخول بين كافة أنوية Gunicorn.
- [x] **مكافحة السبام بالنماذج العامة (Honeypot):**
  - حقول مصيدة مخفية (`website_hp`) في نماذج الحجز والاتصال لإسقاط طلبات روبوتات الإعلانات آلياً.
- [x] **تحديد معدل الطلبات للواجهات العامة (Rate Limiting):**
  - سقف 5 طلبات حجز أو رسائل اتصال لكل 10 دقائق من نفس عنوان الـ IP لمنع الإغراق وهجمات DoS.

## 7. جاهزية بيئة الإنتاج وخلو الكود من الأخطاء

- [x] **إيقاف وضع التطوير:** `DEBUG = False` في إعدادات الإنتاج والـ Staging.
- [x] **حظر مفاتيح Django التجريبية:** التأكد من توليد `SECRET_KEY` عشوائي بطول 50+ خانة في بيئة الإنتاج الحقيقية.
- [x] **عزل قواعد البيانات:** قاعدة بيانات الإنتاج (`alsayyad_clinic_db`) معزولة تماماً عن قاعدة بيانات الـ Staging (`alsayyad_clinic_staging_db`).
- [x] **اجتياز كافة الاختبارات الآلية:** نجاح **37 اختباراً مؤتمتاً بنسبة 100%**.
